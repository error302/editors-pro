# Sharing, settings and 120 fps verification - 1 November 2026

This extends the earlier editor workflow verification. Earlier APK hashes apply to the previous testing build, not these changes.

## Changes

- Completed exports offer YouTube, TikTok, Instagram, Facebook, X and More sharing, plus editable/copyable captions. Android checks installed intent handlers, stages a unique atomic private cache copy, and grants receiving apps read access through a narrowly scoped FileProvider. Source exports and projects are preserved. Handoff is not a publication receipt; the user finishes posting in the destination app. No social posts are authorized or performed during QA.
- SharedPreferences is the canonical settings store. Four legacy Drift preferences migrate once, with a completion marker only after successful writes. Legacy rows remain available for recovery. Invalid stored types/choices normalize; failed writes remain visible and retryable. New project defaults and autosave read this store. Saved project dimensions/FPS remain project-specific; export starts with the saved project's dimensions/FPS and chosen default codec. Unsupported hardware, proxy, AI and demo-caption controls no longer promise working functionality.
- Project/export controls offer 24, 25, 30, 50, 60 and 120 fps. Frame stepping derives timestamps from frame indices; toolbar timecode handles integer high rates. Android queries the default encoder selected by MIME for size/rate/alignment/bitrate support before native preparation. A failed check rejects the export instead of silently exporting at 30 fps. Cancellation during preflight starts no native export.
- FFmpeg seek targets use global microseconds, seeking flushes buffered decoding, frame selection holds the preceding frame and delayed B-frames drain correctly. Missing video packet durations are supplied before rescaling so the final frame has its full duration. Existing AAC fixes are retained.
- Editor preview remains approximately 15 fps and saved project previews approximately 12 fps. These controls do not promise real-time 120 fps preview or recording. Hardware capability reporting does not prove encoder configuration, sustained throughput, every resolution or thermal behavior. A lower-rate source cannot gain new captured frames simply by exporting at 120 fps.
- TikTok's current Content Posting API accepts 23-60 fps; export guidance suggests 60 fps or lower for TikTok. The app-sharing destination may apply its own processing. Direct publishing remains future work described in [the roadmap](social-publishing-roadmap.md); OAuth developer applications, provider access, account permissions and durable publishing jobs are not supplied by Android sharing.

## Reproduction

Generate the two-second numbered 120 fps all-keyframe and normal-GOP fixtures with `python scripts/generate_120fps_fixtures.py`. Run `scripts/test_android_audio.ps1 -TestName high_frame_rate_workflow` to compile the selected Android integration executable and run it from its own retained `/data/local/tmp` directory. Its export checks rate, frame count/order/identity, video duration, and finite distinct stereo tones. `EDITORS_PRO_QA_OUTPUT_DIR` retains the encoded output for independent inspection. The runner never changes app data or foreground UI.

Primary media requirements: [TikTok media transfer guide](https://developers.tiktok.com/docs/en/content-posting-api-media-transfer-guide), [YouTube upload encoding guidance](https://support.google.com/youtube/answer/1722171?hl=en).
